# Live observation API — v1 drafts

Two draft contracts, `contracts/public-map/v1` and `contracts/observations/v1`, specify this API; the rest of this document is target design. The authorized projection is served by the facade in `reader-backend/` (not deployed); the anonymous feed is described from the reference Backend's behaviour, and nothing in this repository serves it yet. This enables an anonymous public activity map and separately authorized diagnostic clients without exposing private Backend internals.

## Architecture and transport

A Backend normalizes packet reception evidence from permitted sources. It exposes two **separate projections** over that model, with independent authorization, retention and response schemas:

- `/api/public/v1` (`GET /nodes`, and `GET /events` with a `since` cursor): anonymous, allow-listed public catalogue and **polled**, short-lived activity (not SSE). Its machine-readable contract is [`contracts/public-map/v1`](../contracts/public-map/v1/openapi.yaml) (`1.0.0-draft.1`, with synthetic fixtures and 22 replayable cases), separate from `contracts/observations/v1`, which covers the authorized projection only. The reference Backend's shipped anonymous map feed is the behaviour it describes. The earlier target path `/api/observations/v1/public` is superseded by it.
- `/api/observations/v1/authorized`: session-authenticated, capability-scoped fleet/user diagnostic catalogue, snapshot and SSE activity.

No client connects directly to MQTT, storage or raw ingress. The authorized projection uses HTTPS JSON REST snapshots and SSE subscriptions; the public feed is plain polled JSON. The public map never calls the authorized endpoints.

## Public projection

- `GET /nodes`: every listed node, sorted by `public_node_id`. A node is listed only when it advertises a position of its own (never an operator's entry or an estimate; a position within one degree of (0, 0) on both axes is a no-fix value and drops the node), has a public type, and was heard through an eligible public source (one the instance's owner operates or approved for publication). Its name is the name it advertises. An empty feed is 200 with an empty list.
- `GET /events?since=`: the transmissions published within the last 45 seconds, or with `since` the events after that opaque, signed cursor. The response carries the next `cursor` and `poll_after_ms`, the earliest the client may poll again. A transmission expires 45 seconds after its first reception and is never returned after that. A cursor is accepted for 45 to 60 seconds; an older, unknown or forged one is 410 `cursor_expired`, and the client fetches `/nodes` again and polls without a cursor. At most 200 events per response; a per-address request limit answers 429 with `Retry-After`; a polling client that honours `poll_after_ms` is never limited. A node that stops being eligible is dropped and announced once as `node_revoked` within 45 seconds. Both operations answer 404 when the instance owner has switched the feed off.
- No credential is read: a caller who sends a session or a token gets exactly the anonymous answer. There is no snapshot operation and no stream.
- Publication is **deny by default**: node/source owner approval, consent, permitted redistribution and revocation are prerequisites. Coarsen or omit coordinates when disclosure would identify a private location. Do not publish unapproved sender/observer IDs, exact private positions, payload, packet hashes, private channel/identity, RSSI/SNR, RF route, internal source names or endpoints.
- No public event represents a proven end-to-end RF route unless that exact claim is independently evidenced and approved; otherwise present only observed activity. Public event IDs must not be linkable to private event IDs.
- Bound public history, frequency, per-node activity and rate to reduce tracking. The server defines and documents conservative TTL and aggregation thresholds before enabling a live feed. Consent revocation invalidates current snapshots/cursors and removes affected public data. The site must not replay expired events as live.
- Synthetic fixtures are prominently marked as demonstration, never as real traffic.

## Authorized projection

The machine-readable draft is [`contracts/observations/v1/openapi.yaml`](../contracts/observations/v1/openapi.yaml) (`1.0.0-draft.4`, with synthetic fixtures and replayable conformance cases). It defines `GET /observers`, `GET /snapshot` and the SSE `GET /events` under `/api/observations/v1/authorized`, always with `scope=self` (the observers the caller may see under the server's rules: own fleet, fleets sharing with it, approved public sources). Same-origin, session cookie, the Reader API's error body, GET-only so no CSRF token. It carries no transmitter location, route or path field, decrypted content, raw bytes or packet hash. The anonymous public projection is not defined there. Where this prose and the OpenAPI differ in a field name, the OpenAPI wins (it uses `/observers`, `/snapshot?since=` and `/events` with `reception`, `resync_required` and `access_revoked` envelopes).

- `GET /authorized/snapshot` and `GET /authorized/events` (with `scope=self`, a `cursor` or `since`, per the OpenAPI) require a session and server-side capability checks on **every** request and reconnect.
- A caller whose `capabilities.observations` is `forbidden` (no grant) gets 403 `forbidden` from every operation alike; when it is `unavailable` (not served, or not reachable now) every operation answers 503, which a client retries. A caller who may observe but sees no observer gets 200 with nothing in it (an empty list, an empty snapshot, a stream of heartbeats only), so a status never reveals whether there is anything to see.
- Authorized event fields may include `event_id`, `packet_correlation_id`, `reception_id`, `observer_id`, `observed_at`, `received_at`, `clock_confidence`, `transport`, `packet_kind`, `rssi`, `snr` and `provenance`, only where the user's scope permits. Every authorized item is a **direct reception**: something an observer recorded. Nothing inferred is served: no route, relay, hop path or delivery state. A field that is `null` (for example `rssi` or `snr`, or an observer's `location` when the caller may not see it) means **not reported**, never an estimate or a guess. If an inferred item is ever offered (a computed path, a delivery estimate), it comes as its own field under a new contract version, never mixed into receptions. Each reception has a distinct ID; correlated receptions may share a packet correlation ID without implying a known route. An `observer_id` is scoped to the caller: two callers who see the same observer get different ids for it, one caller's id is stable across the observer list, snapshot, stream and sessions, and it reveals no ordering, count or row identity and never has the form of an event, reception or correlation id or a cursor.
- Authorization to operate a fleet or Backend does **not** imply permission to decrypt another user's private messages. No decrypted plaintext in the observation feed. Limit raw packet bytes to a separate, explicitly authorized future contract if ever required.
- Optional bounded capture subscriptions require a distinct capability, expiry, rate limits and audit events.

## Stream and failure semantics

This section describes the authorized projection; the public feed's own cursor, expiry and limit rules are in its contract (see above). Snapshots and SSE events carry opaque scoped cursors, event IDs, UTC timestamps, schema version and source freshness. Clients deduplicate by event ID, reconnect using the last cursor, and fetch a fresh snapshot when the cursor expires, falls outside retention or access changes. Delivery is at least once while a cursor is valid; no global ordering or completeness guarantee. Emit heartbeat, `resync_required` and `access_revoked` signals as appropriate. Set explicit server-side stream and memory bounds, backpressure, per-client concurrency and rate limits before rollout. HTTP errors: 401, 403, 404, 410 (expired cursor), 429, 503.

## Acceptance and safety

Publish sanitized OpenAPI/AsyncAPI schemas and synthetic fixtures for public, authorized, empty, expired, duplicate, delayed, multi-observer and revoked states. Test consent withdrawal, observer/identity inference, cross-fleet authorization, private-location suppression, dedup, reconnect, clock skew and sustained load. Public UI must degrade safely to a static explanation or clearly labeled synthetic preview when the approved feed is unavailable. Production enablement and performance thresholds require independent acceptance; this specification does not authorize public data publication.

## Reader Map tab

The Reader's Map tab calls the authorized projection only while `session.capabilities.observations` is `available`, and otherwise shows the unavailable or forbidden state. It draws a pin only for an observer with a non-null `location`; every observer, including those without a shared location (marked "location not shared"), is in the list, which is the primary accessible representation. A live reception highlights its observer for 10 seconds with the reception time. The Map never draws a line, path or area between observers, never places a transmitter and never animates a route: correlated receptions share a `packet_correlation_id` and nothing more.

Pins are drawn on a plain SVG canvas with an equirectangular projection fitted to the located observers, with **no base-map tiles**. The Reader's CSP (`connect-src 'self'`, `img-src 'self' data:`) blocks third-party tile servers by design. Real base-map tiles would need a CSP change and a privacy decision (a tile provider learns the viewer's IP address and the area being viewed), made by the owner and recorded in the decision register, or a same-origin tile proxy with its own retention rules. Neither is part of this version.
